## Per-feature breakdown

### F1 — Keyword blocking (Pro)
**Files:** `content/content.js`, `content/styles.css`, `options/options.html`, `options/options.js`.
- `applyKeywordBlocks()` runs inside `applyBlockers()` (hooked into the existing MutationObserver pass — debounced 100 ms, no extra observer churn).
- Match: case-insensitive `indexOf` substring across video-card titles (`#video-title`, `a#video-title-link`, `yt-formatted-string#video-title`). Hide via `data-cf-keyword="1"` attribute + a single CSS rule.
- Zero-CPU when `hiddenKeywords` is empty or user is free-tier (early return).
- Storage write capped at 200 entries, deduped + lowercased + trimmed in `saveKeywords()`.
- No regex from user input — safe and fast.
- Re-runs on `yt-navigate-finish` SPA navigation and on every `chrome.storage.onChanged.hiddenKeywords` event.

### F2 — Onboarding presets
**Files:** `popup/popup.js`, `popup/popup.css`.
- First-install path: `onboardingComplete === false` → `renderOnboarding()` builds a 3-card view in-place of the toggle grid.
- 3 presets — "Just no Shorts" (1 blocker), "Focused" (4 blockers; marked **MOST POPULAR**), "Minimal" (8 blockers). Plus a "Skip" link.
- For free users on "Focused" / "Minimal": enable only the first 2 free-tier blockers in preset order, then open the existing upsell modal automatically.
- `onboardingChoice` is stored (no analytics network call) so the user can introspect their own pick from DevTools if they ever want.
- Existing users are exempt: `_migrateForV140()` auto-sets `onboardingComplete = true` when settings already have any truthy entry.

### F3 — Review prompt after 5 popup uses
**Files:** `popup/popup.js`, `popup/popup.css`.
- `usageCount` increments on every popup mount.
- When count crosses `REVIEW_THRESHOLD = 5` **and** `reviewPromptShown !== true`, a small `.cf-review-banner` is appended above the footer.
- Clicking **Leave a review** opens `REVIEW_URL` (placeholder `REPLACE_WITH_FINAL_ID` — explanatory comment in code).
- Clicking **Maybe later**, **and** the `pagehide` event when the popup closes, both mark `reviewPromptShown = true`. The user never sees it twice.
- One impression, then quiet forever.

### F4 — Pomodoro Focus Lock (Pro)
**Files:** `background.js`, `options/options.html`, `options/options.js`, `options/options.css`, `popup/popup.js`, `manifest.json`.
- Pro-gated by `STATE.paid` checks in the options UI.
- Options page: configurable focus (15-60 min), break (3-15 min), cycles (1-8). Same PIN required to start.
- `cf:pomodoro-start` handler in `background.js` writes `focusLock.pomodoroState = {phase:"focus", cycle:1, total, until}` and arms `chrome.alarms.create({when})`.
- Phase alarm fires → either swaps to `break` (clears `activeUntil`) or back to `focus` (resets `activeUntil`) or finalises (clears `pomodoroState`, sets `lastPomodoroComplete`).
- Each transition fires `chrome.notifications.create` with a brief title/body.
- Popup banner (`renderFocusBanner`) renders Pomodoro state with priority over the standard focus countdown: `FOCUS m:ss · Cycle n of N` or `BREAK m:ss · Cycle n of N`.
- Restart-safe: state lives in `chrome.storage.local`, alarms persist in `chrome.alarms` storage, popup re-reads on open.
- `cf:pomodoro-cancel` (graceful disable from options page) clears the alarm and resets state.
- Standard Focus Lock behaviour untouched — Pomodoro is a parallel branch keyed by `pomodoroState !== null`.

### F5 — 4 new blockers
**Files:** `content/blockers.js`, `content/styles.css`, `popup/popup.js`, `background.js`.
- `playables` (Pro) — `ytd-rich-shelf-renderer:has(#title yt-formatted-string[title="Playables"])` + `ytd-playable-shelf-renderer`.
- `merch-shelf` (free) — `ytd-merch-shelf-renderer`, `yt-merch-shelf-renderer`.
- `breaking-news` (free) — `ytd-rich-section-renderer:has(yt-formatted-string[title="Breaking news"|"News"])`.
- `mixes-playlists` (Pro) — `ytd-radio-renderer`, `ytd-compact-radio-renderer`.
- All default OFF for everyone (new install + migration both seed `false`).
- Popup blocker grid now lists 14 entries; the Free-tier 2-cap logic and the upsell-on-click-Pro logic continue to work unchanged.

### F6 — Per-page rules (Pro)
**Files:** `content/content.js`, `options/options.html`, `options/options.js`, `background.js`.
- `STATE.perPageEnabled` defaults `false`. When `false`, behaviour is byte-identical to v1.3.5.
- `STATE.perPageSettings` shape: `{ homepage: { <blockerId>: "on"|"off"|"inherit" }, watch: {...}, subscriptions: {...} }`.
- Content-script merge logic in `_effectiveSettingFor(id)`: page-specific override wins over the global toggle when not "inherit".
- Page detection runs from `location.pathname` and is cached per SPA navigation (the existing `yt-navigate-finish` listener triggers `applyBlockers()` which re-evaluates pageKey once).
- Options page ships an enable toggle for v1.4.0; the full tabbed popup UI for editing per-page overrides is queued for v1.5.0. Power users can already write to `chrome.storage.local.perPageSettings` directly to test.

## Migration logic

`background.js → _migrateForV140()` runs on `onInstalled` with `reason === "update"`:

1. Reads the entire `chrome.storage.local` object.
2. Builds a patch: only writes new keys with defaults if they're missing. Existing values are never clobbered.
3. Auto-marks `onboardingComplete = true` for upgraded users with any truthy blocker setting — they don't see the onboarding screen.
4. Initialises `focusLock.{mode,pomodoro,pomodoroState}` without touching `pinHash` / `pinSalt` / `activeUntil`.
5. Writes the patch with a single `chrome.storage.local.set(patch)` call.

## Manual testing checklist for you

1. **Fresh install:** Remove + Load unpacked. Popup should show the 3-card onboarding view, **not** the toggle grid. Pick a preset → settings written, view flips to grid.
2. **Migration:** Roll back to v1.3.5 zip first, install, configure 2-3 blockers. Then upgrade by loading the v1.4.0 folder. Open popup — should go straight to the toggle grid (onboarding skipped) with previous toggles intact, plus 4 new blockers visible and OFF.
3. **F1 keywords:** Options → Hidden keywords. Add `reaction\nclickbait\ndrama`. Save. Reload youtube.com homepage. Cards whose title contains those words should hide.
4. **F4 Pomodoro:** Options → set PIN if not set → switch to the Pomodoro panel below → enter PIN → Start. Popup banner shows `FOCUS m:ss · Cycle 1 of 4`. Phase transitions fire notifications.
5. **F3 review:** Open popup 4 times (verify no banner) then 5th open (banner appears under the toggle grid). Dismiss with "Maybe later". Open 10 more times — banner never reappears.
6. **F5 new blockers:** Toggle each in popup. Inspect the DOM with DevTools — the target element should hide.
7. **F6 per-page:** Options → check "Enable per-page rules". Open DevTools storage inspector, write `perPageSettings: {watch: {comments: "off"}}`. On a watch page, comments should be visible even if the global comments toggle is on. Uncheck the option to confirm global behaviour resumes.

## Known limitations / queued for v1.5.0

- **F6 tabbed popup UI** — engine is live, UI wrapper is the missing piece. Pro users opting in today need to set `perPageSettings` via DevTools. v1.5.0 will add the four-tab grid in the popup.
- **Keyword text-extraction** — uses `#video-title` / `yt-formatted-string#video-title`. YouTube ships title-renderer variations; if any card surfaces titles through a different element, that card won't be matched. Adding more selectors is non-breaking.
- **Pomodoro audio cues** — uses `chrome.notifications` for visual + system sound. We don't ship a custom chime (avoids the audio permission and the `notifications` sound asset trap).
