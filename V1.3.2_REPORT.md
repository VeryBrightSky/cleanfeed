# v1.3.2 release report — ExtPay popup defensive fallback

## Summary

A single failure mode in the ExtensionPay SDK's `open_popup()` —
`chrome.windows.create({ left, top, width, height })` rejecting with
*"Invalid value for bounds. Bounds must be at least 50% within visible
screen space"* on high-DPI / multi-monitor setups — caused both the
**Upgrade — $4.99** and **I already paid** buttons to silently no-op
because the async rejection was swallowed by the surrounding handler.

v1.3.2 wraps both calls in an async `try/catch` and falls back to opening
ExtPay's hosted page in a regular browser tab via `chrome.tabs.create`,
which has no off-screen-bounds problem. Same payment flow, same login
flow, just without the small floating popup window.

## Fallback URL map used

| SDK call | Tab fallback URL |
|---|---|
| `extpay.openPaymentPage("pro")` | `https://extensionpay.com/extension/cleanfeed2342?back=choose-plan` |
| `extpay.openLoginPage()` | `https://extensionpay.com/extension/cleanfeed2342/reactivate?back=choose-plan` |

(`openReactivatePage` does not exist on the SDK — `openLoginPage()` already
navigates internally to `/reactivate?api_key=…`. Just one URL needed per
button.)

## How to verify locally (when you can)

1. `chrome://extensions` → Load unpacked → pick the unzipped `cleanfeed/` folder.
2. Open popup → click **Upgrade — $4.99**. On a normal display, you'll get the small ExtPay popup window as before. On a multi-monitor / high-DPI rig that previously failed, you'll see a regular tab open at `extensionpay.com/extension/cleanfeed2342?back=choose-plan` instead.
3. Inspect the service worker's DevTools console — if the SDK threw, you'll see one `[CleanFeed] ExtPay payment popup failed, falling back to tab: ...` line; otherwise nothing new is logged.
4. Same drill for **I already paid**.
